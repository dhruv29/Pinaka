Open-source AI bill of materials

Answer “what AI are we running?” with a list, not a guess.

Pinaka reads a code repository or a running Kubernetes cluster and inventories every model, AI library, hosted provider, model server, vector store, agent tool, GPU and AI credential it finds, with where each one was seen and which ones to look at first.

$ pinaka scan -repo . -kube -format json -out ai-bom.json

          How it runs

          Built to be allowed near production.

          One small program you run on a laptop, in a pipeline or as a nightly job. It asks for as little access as an inventory can.

          1. Nothing goes inside your containers

            No agent, no sidecar, nothing installed in a workload. A single binary with no dependencies.

          2. It only reads

            A repository scan opens files and makes no network calls. A cluster scan uses only kubectl get and never requests secrets. Teams that will not grant cluster access can hand over saved kubectl get -o json output instead.

          3. Credentials by name, never value

            It reports that OPENAI_API_KEY is written into a workload in plain text. It does not copy the key.

          4. Output other systems can use

            A readable report, Pinaka’s own JSON, or a CycloneDX 1.6 document for inventory and compliance tools.
